### Логика и функционал AI (Температура)

#### Хлеб

1) Задача с температурой для пекарни устроена так: у неё в форме есть **свой диапазон** (то, что видно в «Сути задачи» — например, от и до в градусах).

Этот диапазон нужен, чтобы **показать, насколько введённый замер отличается от того, что задали в карточке задачи**:

- если замер попадает в эти границы — пишем, что он **в диапазоне** задачи;

- если выше верхней границы — **превышение** (на сколько градусов);

- если ниже нижней — **понижение** (отклонение со знаком «минус», чтобы было ясно, что температура ниже нормы задачи).

2) Отдельно от этого система смотрит: **какая по смыслу зона по хлебу** для введённой температуры.

Тут возможны два варианта:

- В задаче **указано оборудование для хлеба** (миксер, расстойка, печь, охлаждение и т.п.).

  Тогда режим (опарка, расстойка, выпечка, охлаждение) берётся **из того оборудования**, которое привязано к задаче.

  Тексты «что не так / что делать» и оценка строки замера идут из **настроек, привязанных к этому оборудованию**.

- В задаче **не указано** оборудование для хлеба.

  Тогда используется **общая шкала по умолчанию** — свой набор зон по градусам.

  По введённой температуре выбирается **одна подходящая зона** — из неё берутся формулировки угрозы и действия, а также понятие «норма / предупреждение / критично» для строки замера.

Можно получить текст про выпечку или охлаждение по смыслу зоны, и одновременно строку **«превышение»** или **«понижение»** относительно диапазона из «Сути задачи» — оба показателя выводятся: смысл по хлебу и расхождение с тем, что зафиксировали в задаче.

#### Мясо

1) Задача с температурой для мясного цеха устроена так же: в форме есть **свой диапазон** в «Сути задачи» — от и до в градусах.

Этот диапазон нужен, чтобы **показать, насколько введённый замер отличается от того, что задали в карточке задачи**:

- если замер попадает в эти границы — пишем, что он **в диапазоне** задачи;

- если выше верхней границы — **превышение** (на сколько градусов);

- если ниже нижней — **понижение** (отклонение со знаком «минус», чтобы было ясно, что температура ниже нормы задачи).

2) Отдельно от этого система смотрит: **какая по смыслу зона по мясу** для введённой температуры — охлаждённое хранение или заморозка, и насколько замер «в норме» по этой линии.

Тут возможны два варианта:

- В задаче **указано мясное оборудование** из списка (холодильная камера, морозилка, прилавок, витрина и т.п. — то, что в группах «Мясо — …» при выборе оборудования).

  Тогда понятно, **что мы меряем**: охлаждёнку или морозилку. Смысл берётся **из привязанного оборудования**: если в задаче заморозка — оценка идёт по шкале заморозки (и ноль или плюс у морозилки уже «слишком тепло» для заморозки). Если охлаждённое хранение — по шкале для плюсовых температур в холодильнике, а для ухода в минус — по смыслу «переохлаждение / не та зона».

  Тексты «что не так / что делать» и оценка строки замера идут из **того набора зон**, который соответствует этому оборудованию и выбранному смыслу (охлаждёнка или заморозка).

- В задаче **не указано** такое мясное оборудование.

  Тогда берётся **одна общая шкала по умолчанию** на весь разумный диапазон (от глубокой заморозки до опасного тепла).

  По введённой температуре выбирается **одна строка** из этого набора — из неё же берутся формулировки угрозы и действия, а также понятие «норма / предупреждение / критично» для строки замера.

Оценка строки замера по смыслу мяса **согласована** с этой зоной, а не только с тем, попал ли замер в цифры «Сути задачи» — иначе при широком допуске в карточке можно было бы получить «в диапазоне по карточке», а по смыслу мяса уже нарушение.

Можно получить текст про охлаждёнку или заморозку по смыслу зоны, и одновременно строку **«превышение»** или **«понижение»** относительно диапазона из «Сути задачи» — оба показателя выводятся: смысл по мясу и расхождение с тем, что зафиксировали в задаче.

#### Кофе

1) Задача с температурой для кофейни устроена так же: в форме есть **свой диапазон** в «Сути задачи» — от и до в градусах.

Этот диапазон нужен, чтобы **показать, насколько введённый замер отличается** от того, что задали в карточке:

- если замер попадает в эти границы — пишем, что он **в диапазоне** задачи;

- если выше верхней границы — **превышение** (на сколько градусов);

- если ниже нижней — **понижение** (отклонение со знаком «минус», чтобы было ясно, что температура ниже нормы задачи).

2) Отдельно от этого система смотрит: **какая по смыслу зона по кофе** для введённой температуры — хранение зерна, обжарка или охлаждение после обжарки, и насколько замер «в норме» по выбранной линии.

Тут возможны два варианта:

- В задаче **указано кофейное оборудование** (то, что в группах «Кофе — …» при выборе оборудования: склад, ростер, охладитель и т.п.).

  Тогда режим (**хранение** / **обжарка** / **охлаждение после обжарки**) подбирается по контексту задачи и выбранному оборудованию.

  Тексты «что не так / что делать» и оценка строки замера идут из **трёх разных наборов зон** — отдельно для хранения, отдельно для обжарки, отдельно для охлаждения.

  Каждая зона внутри набора привязана к **своим типам оборудования**. Если в задаче выбрано оборудование **другого типа**, чем у подобранной текстовой зоны, система не подставляет «чужие» красивые формулировки — берётся **запасной набор текстов** из общих правил допуска для этого режима (как при отклонении от контрольных точек).

- В задаче **не указано** кофейное оборудование.

  Тогда используется **одна общая шкала по умолчанию** на весь рабочий диапазон (от холодного склада до перегрева обжарки).

  По введённой температуре выбирается **одна строка** этой шкалы — из неё берутся формулировки угрозы и действия, а также «норма / предупреждение / критично» для строки замера.

В обоих случаях выбор «какая строка описывает замер» делается **одним правилом**: сначала смотрим, есть ли в задаче кофейное оборудование, и от этого переключаемся либо на режимные зоны, либо на общую шкалу.

**Граница 25 °C** для режимов **хранение** и **охлаждение после обжарки** устроена так, чтобы не было путаницы:

- **ниже 25 °C** (в подписях к зонам это оформлено как примерно **+15…+24 °C**) — зона «как задумано» для этих режимов;

- **от 25 °C и выше** — уже зона предупреждения (для хранения это «слишком тепло», для охлаждения — «слишком медленно остывает» и т.п.).

То есть **ровно 25 °C** не считается одновременно «идеалом» и «жёлтой зоной» — это именно начало предупреждения.

Оценка строки замера по смыслу кофе **согласована** с выбранной зоной или строкой общей шкалы, а не только с тем, попал ли замер в цифры «Сути задачи».

Можно получить текст по смыслу кофе и одновременно строку **«превышение»** или **«понижение»** относительно диапазона из «Сути задачи» — оба показателя выводятся.

### План реализации AI (Температура)
### +++

## 1 🟢 **Выполнено** Подготовка структуры AI-модуля

- Есть отдельный модуль анализа температуры для демо.

- Он умеет:

  - отдавать сводку настроек по нишам (мясо, кофе, хлеб);

  - по введённому числу и параметрам задачи строить **вердикт**: в норме, проблема или ввод нельзя обработать;

  - собирать **карточку предупреждения** при проблеме;

  - собирать **карточку «в пределах нормы»** с короткими текстами — но только для ниш мясо, кофе, хлеб;

  - вспомогательно форматировать числа, подписи диапазонов и оценку риска.

## 2 🟢 **Выполнено** Конфигурация ниш и режимов

- Для **мясо** и **хлеб** готовые окна допуска и наклон «насколько страшно отклонение» лежат рядом с наборами зон в соответствующих файлах правил.

- Для **кофе** окна допуска по режимам (хранение / обжарка / охлаждение) и запасные формулировки при «несовпадении» оборудования хранятся **внутри модуля анализа**; сами **полосы по зонам** и **общая шкала без кофейного оборудования** — в отдельном справочнике по кофе (без дублирования туда же второй копии режимных окон).

- Для **мяса** подробно:

  - если в задаче выбрано мясное оборудование — оценка идёт по зонам охлаждёнки или морозилки в зависимости от режима и знака температуры;

  - если мясного оборудования нет — одна общая шкала по умолчанию на весь разумный диапазон;

  - у каждой зоны есть уровень серьёзности: критично / предупреждение / норма (это **не** то же самое, что зелёная/красная галочка в строке замера и не то же самое, что цвет подсказки на экране).

- Для **хлеба** зоны и режимы задаются в своём справочнике; модуль анализа подключает его по общим правилам.

- Для **кофе** подробно:

  - при выбранном кофейном оборудовании подставляется один из трёх режимов: хранение, обжарка или охлаждение — и зоны из соответствующего набора;

  - пороговые значения согласованы с подписями: для **хранения** и **охлаждения** норма **строго ниже 25 °C** в смысле логики зон, а предупреждение **с 25 °C**, чтобы не смешивать «идеал» и «жёлтую зону» на одной и той же отметке;

  - без кофейного оборудования используется только **общая шкала по умолчанию**;

  - проверяется, относится ли выбранная текстовая зона к тому оборудованию, что стоит в задаче.

## 3 🟢 **Выполнено** Ядро анализа

- Сначала из ввода получается число градусов.

- Подставляется контекст ниши и режима и допустимый диапазон из задачи; если в карточке перепутаны верх и низ — они приводятся к виду «от меньшего к большему».

- Для **хлеба**, **мяса** и **кофе** действует **отдельная ветка**: смотрят не только «вписался ли замер в цифры карточки», но и **в какую зону справочника** попала температура; от уровня зоны зависит, засчитать строку как успех или как проблему.

- Для остальных ниш — общая схема: сравнение с диапазоном, расчёт риска по отклонению, тексты при выходе за пределы.

- Если число не разобрать или диапазон нельзя применить — вердикт «некорректный ввод».

## 4 🟢 **Выполнено** UI-адаптер для модалки

- Карточка **проблемы** по умолчанию считается «жёсткой» или «мягкой» по проценту риска; порог задаётся в коде (около семидесяти процентов).

- Для **мяса**, **кофе** и **хлеба** при **критической** зоне подсказка всё равно остаётся **жёсткой**, даже если процент риска ниже порога — там, где это уместно по оборудованию.

- Карточка **«в норме»** показывается только если общий вердикт «в норме» и ниша — мясо, кофе или хлеб; тексты угрозы и действия берутся из той же логики зон, что и в анализе, с учётом «есть ли в задаче своё оборудование по нише».

- Форма полей подсказки на замере зафиксирована в конфиге демо (заголовок, строки отклонения, подпись контрольной точки и т.д.).

- Старые поля «тяжести» без нового поля статуса подсказки приводятся к единому виду при загрузке задач.

## 5 🟢 **Выполнено** Интеграция с модалкой и таблицей замеров

- При вводе температуры с экранной клавиатуры и подтверждении:

  - если строка замера помечается как успешная — показывается зелёный вариант подсказки;

  - если как проблема — жёлтый или красный вариант в зависимости от логики выше;

  - ниша и режим подставляются из задачи.

- То же самое применяется при пересчёте строк из сохранённых данных и при добавлении задач в демо.

- Для полей не про температуру и для таймера подсказка по температуре не показывается.

- Модалка задачи сама анализ не пересчитывает — она читает уже посчитанное в объекте задачи.

- Таблица замеров выводит подсказку из строки замера.

#### Хранение результата

- Подсказка лежит в строке замера; краткий контекст для задачи — в поле контекста задачи.

- При сохранении демо-состояния в памяти браузера уходит текущий снимок.

#### Поля контекста задачи

- В контексте хранятся: движок расчёта, ниша, режим, тип поля, границы контрольной точки, подпись диапазона, время обновления.

#### Поля подсказки в строке замера

- Пусто — если нет числа, нет температурного поля, не вызывался расчёт, это таймер и т.п.

- Заполнено — если для мяса, кофе или хлеба посчиталась норма или проблема по правилам выше.

### Закон цвета AI-блока (показатель → цвет)
### -----

**Что красит строку замера в таблице:**

- берётся **статус подсказки** (спокойно / внимание / серьёзно) из результата расчёта;

- отдельно учитывается **статус самой строки** замера: ожидает ввода, успех, проблема — у них свои стили в таблице.

**Откуда берётся «жёлтость» подсказки:**

- при сохранении замера с клавиатуры и при пересчёте из данных чек-листа статус подсказки копируется из результата «проблема / в норме»;

- при проблеме степень тревоги по умолчанию зависит от процента риска и порога;

- для мяса, кофе и хлеба **критическая** зона по смыслу поднимает тревогу до **серьёзной**, где это задумано;

- при **норме** по анализу для этих ниш подсказка в спокойном состоянии.

**Тексты при нарушении** приходят из того же анализа, что и вердикт по зонам — а не только из «вписался ли замер в min/max карточки».

**Если анализ не дал вердикта** — подсказка может остаться пустой.

#### Стили (по проекту)

- Разметка и оформление строк замера — в компоненте таблицы замеров чек-листа; классы задают фон и отступы строки.

- Оранжевый акцент для предупреждений задан в общих стилях проекта.

- Отдельного «только для AI» класса может не быть — оформление завязано на строку замера целиком.
