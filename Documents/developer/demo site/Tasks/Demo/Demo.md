# План реализации `resources/js/pages/client/Demo.vue`

## Цель

Собрать конверсионную демо-страницу `/{locale}/demo` (Vue 3 + SCSS + Naive UI): layout, секции HACCP/EUDR/отчёты, модалки, persist в `localStorage`, публичные страницы партии и дневного отчёта (отдельные URL, Laravel отдаёт SPA).

#### Шаг 6. Актуальная логика модалки «Новая контрольная точка» (что видно сейчас)

**6.1 Где это отображается**

- Форма создания задачи: `resources/js/components/client/demo/sections/ChecklistsSection.vue`.
- Блоки внутри модалки:
  - `Тип задачи` (radio): `Оборудование`, `Комнаты`;
  - `Предмет задачи` (зависит от `Тип задачи`);
  - `Суть задачи` (один select + панель по выбранному типу поля).
- Read-only в «Детали задачи»: `resources/js/components/client/demo/modals/ChecklistModal.vue`.

**6.2 Что меняется от выбора в `Тип задачи`**

- Если выбран **`Оборудование`**:
  - в секции `Предмет задачи` показывается `select` группы + чекбоксы элементов выбранной группы (источник: `EQUIPMENT_GROUPS`);
  - при сохранении требуется минимум 1 выбранный `equipmentTargetIds`;
  - в `Суть задачи` для типа `Создать заявку` в деталях выводится:
    - `Заявка: <список выбранных предметов из equipmentTargetIds через запятую>`.

- Если выбраны **`Комнаты`**:
  - в секции `Предмет задачи` показываются группы помещений и чекбоксы (источник: `ROOM_GROUPS`);
  - при сохранении требуется минимум 1 выбранный `roomTargetIds`;
  - в `Суть задачи` для типа `Создать заявку` в деталях выводится:
    - `Заявка: <список выбранных помещений из roomTargetIds через запятую>`.

- Тип `Никто (отдельная задача)` удалён из модалки создания.

**6.3 Что сейчас в `Суть задачи`**

Секция `Суть задачи` сейчас содержит только 3 пункта в select:

- `Введите температуру` (`temperature`)
- `Выберите один ответ` (`single_choice`)
- `Создать заявку` (`ticket`)

Поведение по каждому пункту:

- **`Введите температуру`**
  - отображается: 2 обязательных поля `Минимум, °C` и `Максимум, °C`;
  - валидация: оба значения должны быть числом;
  - в данных задачи (`taskFieldDefinitions[].config`): `minC`, `maxC`, `label` (нормализуется как `Температура`).

- **`Выберите один ответ`**
  - отображается: обязательное поле `Вопрос`, минимум одно обязательное поле `Ответ`, кнопка `Добавить вариант`;
  - валидация: `question` непустой, каждый `options[]` непустой;
  - важно: блок `Ответы исключений` для этого типа **не показывается** и **не валидируется**;
  - в данных задачи: `question`, `options[]`.

- **`Создать заявку`**
  - отображается: текст-пояснение + обязательный `Textarea` `Описание задания`;
  - валидация: `description` обязателен;
  - в данных задачи: `description`;
  - в «Детали задачи» строка `Суть задачи` выводится как:
    - `Заявка: <description из textarea>`.

**6.4 Ответы исключений (текущее правило)**

- Блок `Ответы исключений` показывается для выбранных типов поля, кроме `single_choice`.
- Для типов, где блок показан, при сохранении требуется минимум 1 непустая строка.
- Эти строки сохраняются в задачу как `correctiveActions`.

**6.5 Панель выполнения задачи (текущее состояние, важно для рефакторинга по типам)**

Где находится:

- Панель выполнения открывается в `resources/js/components/client/demo/modals/ChecklistModal.vue` 
по клику на статус `pending` в таблице замеров (если задача не запланирована на будущее).
- Это правый `drawer` внутри модалки `Детали задачи`.

Когда открывается:

- В таблице замеров у строки со статусом `pending` кнопка активна только если `startDate <= сегодня`.
- Для задач, запланированных на будущую дату, `pending` отображается без открытия панели.

Что приходит в панель (входные данные):

- Ссылка на текущую задачу (`props.task`), включая:
  - `taskFieldDefinitions` (первый тип поля используется как базовый тип панели);
  - `measurements` (конкретная выбранная строка `pending`);
  - `equipmentTargetIds` / `roomTargetIds` (для строки контекста в панели).
- Текущий слот замера (`pendingDrawerMeasurement`): `time`, `value`, `status`.

1) Что сейчас отображается в панели для типа `temperature`:

- Заголовок задачи.
- Блок с ошибкой оборудования (`Error equipment`) — показывается только для `temperature` и legacy `timer`.
- Строка контекста (список выбранных объектов/помещений).
- Поле ввода значения (температура), с префиксом/суффиксом.
- Экранная клавиатура:
  - цифры;
  - `.`, `DEL`, `+/-`, `✓`.
- Кнопка камеры (mock), счетчик `N фото` и список названий всех добавленных фото.

Что записывается из панели для типа `temperature` (на `✓`):

- В выбранный слот `measurements[]` записывается:
  - `value` в формате `"<число> °C"`;
  - `status`:
    - `success`, если значение в диапазоне `minC..maxC` из `taskFieldDefinitions[0].config`;
    - `problem`, если вне диапазона.
- Данные пишутся напрямую в объект задачи (реактивная мутация), затем сохраняются через общий `demoState` watcher.
- Фото из панели выполнения сейчас **не** сохраняется в задачу как отдельные поля (это локальная имитация в текущем открытии панели).

Фиксация статуса по спорному вопросу (чтобы не возвращаться):

- В текущей реализации **уже есть** glove-friendly ввод температуры:
  - крупные кнопки numpad;
  - инструменты `.`, `DEL`, `+/-`, `✓`;
  - работа внутри `pending drawer` в `ChecklistModal.vue`.
- В текущей реализации **уже есть** Bluetooth-error alert:
  - сообщение `Error equipment`;
  - текст «Блютуз устройство не доступно или выключено»;
  - показывается для `temperature` и legacy `timer`.
- Что **не сделано**:
  - отдельный самостоятельный экран/маршрут для температурного ввода (`TempInput.vue`);
  - отдельный расширенный Bluetooth flow (state machine `retry/reconnect/fallback`)

    - вынести температурный flow в отдельный переиспользуемый модуль;
    - добавить полноценный Bluetooth state-flow;
    - сделать live-мониторинг mock + эскалации в UI.
  - `P1`:
    - внедрить PWA и offline queue;
    - добавить быстрый поиск `Ctrl+K`.
  - `P2`:
    - реальный PDF-экспорт;
    - карта инспектора;
    - drag-and-drop виджетов;
    - voice input с fallback.

- Этап A. Температурный сценарий как самостоятельный модуль (`P0`):
  - создать `TemperatureExecutionPanel.vue` и вынести туда текущий `temperature/timer` drawer-flow;
  - оставить обратную совместимость: подключение через `ChecklistModal.vue` без изменения контракта задачи;
  - подготовить режимы рендера:
    - desktop: правый drawer;
    - mobile: fullscreen-режим с крупными touch-элементами;
  - критерий приёмки:
    - функционально 1:1 с текущим поведением;
    - запись в `measurements` и определение `success/problem` не меняются.

- Этап B. Bluetooth state-flow (`P0`):
  - внедрить явные состояния:
    - `connected`;
    - `disconnected`;
    - `reconnecting`;
    - `manual`;
  - добавить действия:
    - `Повторить подключение`;
    - `Перейти на ручной ввод`;
  - предусмотреть timeout и fallback в `manual`;
  - критерий приёмки:
    - нет тупикового состояния;
    - сохранение замера работает во всех состояниях.

- Этап C. Live monitoring и эскалации (`P0`):
  - добавить mock-поток изменений (таймер/интервал) для demo-сенсоров;
  - синхронизировать Dashboard и Hot tasks с изменениями статусов;
  - добавить эскалации:
    - toast/alert в интерфейсе;
    - звук (desktop при разрешении браузера);
    - вибро (mobile при поддержке API);
  - критерий приёмки:
    - статусы и счётчики обновляются в реальном времени без перезагрузки.

- Этап D. PWA и offline queue (`P1`):
  - добавить `manifest.json`, иконки, service worker;
  - ввести `offline badge` в шапке;
  - реализовать demo-очередь операций:
    - при offline действия сохраняются локально;
    - при online очередь автоматически отправляется;
  - критерий приёмки:
    - замеры, внесённые offline, не теряются и синхронизируются после восстановления сети.

- Этап E. Быстрый поиск и навигация (`P1`):
  - реализовать command palette `Ctrl+K`:
    - поиск по задачам;
    - переход к секции/карточке;
    - фильтрация по статусу и ответственному;
  - mobile-режим:
    - отдельная кнопка поиска в верхней панели вместо hotkey;
  - критерий приёмки:
    - переход к нужной задаче за 2–3 действия.

- Этап F. Публичные артефакты инспекции (`P2`):
  - заменить mock PDF на реальный генератор с данными текущего состояния;
  - добавить в публичный отчёт явные поля:
    - кто подтвердил;
    - когда подтверждено;
  - добавить карту инспектора (Leaflet) с fallback-текстом при недоступности карты;
  - критерий приёмки:
    - PDF и публичная страница содержат фактические данные демо-состояния, а не заглушки.

- Этап G. Визуальные и UX-расширения (`P2`):
  - drag-and-drop для виджетов Dashboard с сохранением порядка в `localStorage`;
  - voice input для температуры с fallback на numpad;
  - haptic/confetti как опциональный слой (без влияния на бизнес-логику);
  - критерий приёмки:
    - отключение этих эффектов не ломает функциональные сценарии.

- Риски и митигации:
  - риск регресса в `ChecklistModal.vue`:
    - вынос через адаптер-компонент с теми же входными/выходными контрактами;
  - риск разъезда desktop/mobile:
    - единая state-логика, разный только UI-слой;

    - feature-detection + fallback ветки для notifications/vibrate/voice/PWA;
  - риск перегруза демо:
    - feature flags для поэтапного включения новых фич.
