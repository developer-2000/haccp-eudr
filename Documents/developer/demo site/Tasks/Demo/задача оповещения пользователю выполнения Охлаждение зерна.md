
# Реализация задачи оповещения пользователю выполнения задачи «Охлаждение зерна»


## Логика работы задачи

 - Сценарий живёт только если у задачи «Охлаждение зерна» в данных есть хотя бы один статус времени выполнения 
задачи со статусом **pending**. Если такого статуса нет — цепочка оповещения не подключается.

 - Дальше смотрит в **sessionStorage** (ключ из config.js):
   - если в прошлой сессии уже был **полный цикл**
   - показали оповещение **и** отсчёт дошёл до конца (таймер отработал)
   - повторно тост и полосу не показываем;
   - если тост успели показать, но пользователь ушёл со страницы **до конца отсчёта**
   - считаем цикл незавершённым: при следующем заходе снова предлагается **полная** цепочка
   - новое оповещение и новый отсчёт, как в первый раз.

 - Когда сценарий разрешён и полный цикл в storage ещё не зафиксирован:
   - Запоминается индекс обьекта времени в задаче со статусом `pending`
   - только он может позже перейти в статус problem по таймеру.
   - Через паузу из конфига (после монтирования приложения) показывается оповещение и звук, 
   фиксируется факт показа и время старта в store и в sessionStorage.
   - Сразу после вызова оповещения показывается **красная полоса** под header сайта с тем же смыслом и кнопкой перехода к чек-листам. 
   Полоса сама по таймеру страницы **не** появляется — только в этом же шаге, что и оповещение.
   - На полосе идёт обратный отсчёт до момента автоматического перевода замера в статус **problem** 
   (если к тому моменту замер всё ещё `pending`). Когда отсчёт доходит до нуля — полоса скрывается; 
   глобальный тост «Время выполнить задачу», если он ещё открыт, закрывается тем же событием.
   - По отдельному таймеру после оповещения система пытается выставить **problem** именно у того замера, 
   индекс которого был зафиксирован на старте. Если пользователь уже успел изменить статус — ничего лишнего не изменятся.
   - После срабатывания этого таймера в storage отмечается **логическое завершение отсчёта**
   признак, что цикл «тост → ожидание → попытка problem» прошёл до конца.
   - Пользователь может перейти к задаче из оповещения или из полосы
   открывается демо-секция чек-листов, открывается модалка задачи, а после неё открывается модалка решения задачи.
   - Когда сценарий по данным больше не актуален (например, не осталось нужного `pending`) — полоса сбрасывается, лишнее не висит в интерфейсе.


## Задействованные файлы (сценарий `task_grain_cooling`)

### Ядро сценария (`task_grain_cooling/`)
- `config.js` — `task_grain_cooling`, тайминги, тексты, lock/unlock индекса замера
- `taskGrainCoolingStore.js` — Pinia, `sessionStorage`, логическое завершение цикла (тост + отсчёт)
- `useGlobalTaskReminder.js` — тост, звук, таймер `problem`, полоса только после тоста
- `grainCoolingDemoEntry.js` — точка входа, `scenarioProcessAllowed`, сброс полосы
- `applyGrainCoolingMeasurement.js` — `pending` → `problem`, `hasGrainCoolingPendingMeasurement` и др.
- `GrainCoolingNotificationBanner.vue` — полоса под шапкой, отсчёт, переход к чек-листам
- `GlobalTaskReminderToast.vue` — разметка глобального тоста
- `grainCoolingNavigateToDemoChecklists.js` — переход на демо + диплинк в store
- `grainCoolingIndexedAccess.js` — доступ к замеру по индексу из конфига
- `resolveGrainCoolingTaskFromDemoState.js` / `getGrainCoolingTaskFromDemoState` — задача из `demoState`
- `taskGrainCoolingLog.js` — отладочные логи сценария
- `task-grain-cooling-toastify.scss` — стили тоста (подключается из `app.js`)
- `index.js` — реэкспорт публичного API фичи
